# 仕様対応と検証記録

実装日：2026-09-08。提供されたゲーム開発仕様に基づく対応状況です。

## 対応状況

| 仕様 | 実装 |

| 自由な家づくり | 16種類のお菓子。6カテゴリ。配置・移動・重ね置き・片付け・取り消し。初期のおうちを飾る／空の庭から作る。 |
| 型抜き | 生地をタップするとクッキーが増える。約30秒で壁を2種類解放。 |
| チョコがけ | 指でなぞるとチョコの渦が動く。約30秒で屋根を1種類解放。 |
| キャッチ | 材料をカゴへドラッグ／材料→カゴの順にタップ。約35秒で飾りを2種類解放。落ちた材料は再登場。 |
| オーブン | 生地を入れて約30秒待つ演出。土台を2種類解放。ドラッグと2回のタップを利用可能。 |
| 保存・再編集 | IndexedDBの編集中自動保存と、サムネイル付きアルバム。アプリ側の件数上限なし。 |
| 誤操作への配慮 | 取り消し、減点なし、新規作成・別作品切替前の保存。保存失敗時は元の作品を維持。 |
| 音設定 | BGM・効果音・声かけの切替。歯車は控えめに配置、計算で設定を開く。 |
| 水彩風の世界観 | 専用生成背景と透明なお菓子パーツ。庭にウサギ、配置時に粒の演出。 |
| オフライン | 全実行ファイル・素材を事前キャッシュ。初回キャッシュ失敗は準備完了にしない。 |
| 課金・広告・外部共有なし | 該当機能や解析通信を実装していない。クラウドDBなし。 |
| 成果物 | `dist/` のWebアプリ、READMEの起動手順、LICENSES.md。 |

## 実行済みの確認

`npm run check`：JavaScript構文、ローカル参照、PWAマニフェスト、必須素材の存在を確認。Webアプリ一式14ファイル、約1.87MiB。

`npm test`：10テスト成功。

1. ミニゲームごとの解放が1〜2種類、繰り返しても既存パーツを失わない。
2. 4種類を遊ぶと全16パーツが使用可能になる。
3. 家とパーツのIDが独立し、移動先が画面外へ出ない。
4. 手前のパーツを選び、表示順の計算で保存順を勝手に変えない。
5. 取り消しで移動・削除前の独立したスナップショットに戻る。
6. 不正な保存レコードを描画前に排除する。
7. 全配信素材がService Workerの事前キャッシュ対象に含まれる。
8. 模擬オフライン環境でHTML・画像をネットワークなしで取得する。
9. 他アプリのキャッシュを削除しない。途中で失敗した初回ダウンロードを有効化しない。
10. 他ドメインやPOSTリクエストを横取りしない。

以上はNode.js上のモデル・Service Worker制御のテストと静的検証です。ブラウザを使ったE2Eテスト、iPad/Safari実機、実際のIndexedDB、ホーム画面への追加、端末を機内モードにした再起動、実音声再生は未確認です。

## 制約

- 日本語の声かけは、端末内の日本語音声が利用できる場合のみ。ネットワーク音声には切り替えない。
- 保存は端末・ブラウザ・配信URLごと。端末間同期やバックアップ書き出しは今回の対象外。
- キャッシュや作品データは、端末の容量不足・サイトデータ削除などで失われる可能性がある。
- 新しいURLへ配信し直しても、旧URLの作品は自動で移動しない。
- ゲームのアカウント登録はない。確認用の非公開ホスティングにアクセス認証がある場合は、配信サービス側の認証が最初に必要になる。
- iPad実機で操作とオフライン起動が通るまでは、実機動作確認済みとは扱わない。
